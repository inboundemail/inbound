---
title: "Junk Filter"
description: "How Inbound marks spam and threats as junk, and how to tune it"
---

Inbound checks every received email for spam, phishing, fraud, malware and impersonation. Emails that cross your account's threshold are marked as **junk**. Junk mail is never dropped:

- **Webhooks** still receive it, with `email.spam.isJunk: true`. See [Webhook Structure](/api-reference/webhook#junk-filter-verdict).
- **IMAP** shows it in the `Junk` folder instead of `INBOX` and the scope folders. See [IMAP Behavior](/mailboxes/imap-behavior#junk).
- **The mailbox API** lists it under `folder=junk`, and the email API returns `spam.is_junk`.

## Filter levels

Set the level in the [Mailboxes & SMTP dashboard](https://inbound.new/mailboxes) or with `PUT /api/e2/spam-filter`. It applies to the whole account and to emails received after the change.

Each email gets a level from 0 (none) to 4 (clear) for spam, phishing, fraud, malware and impersonation, plus how confident the classifier is in its answer. Failed authentication (for example a DMARC failure) can raise a level without making the classifier more confident, so the default level only acts on confident answers.

| Level | Marks as junk when any of them is |
| --- | --- |
| `strict` | Level 3 or higher, or level 2 with a confident answer |
| `standard` (default) | Level 3 or higher with a confident answer |
| `lenient` | Level 4 with a confident answer |
| `off` | Nothing automatically |

Prompt injection (text aimed at an AI reading the email) is checked too, but never marks an email as junk by itself. An attachment that fails the receiving server's virus scan counts as clear malware.

Unless the level is `off`, an email that fails the receiving server's spam check is also marked as junk.

```bash
curl -X PUT https://inbound.new/api/e2/spam-filter \
  -H "Authorization: Bearer $INBOUND_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"level": "strict"}'
```

## Guard rules

Guard rules take precedence over the filter level:

- The `junk` action marks matching emails as junk without blocking them.
- The `allow` action marks matching emails as not junk, even if the filter would flag them.
- The `block` action still blocks delivery entirely.

## Correcting a verdict

Moving a message between `INBOX` and `Junk` in an email client, or setting `isJunk` with `PATCH /api/e2/mailboxes/{id}/messages/{messageId}` or `is_junk` with `PATCH /api/e2/emails/{id}`, records your decision for the email across the account. Automatic verdicts never override a decision you made.

The webhook and API report why an email was marked: `classifier`, `ses_spam`, `guard_rule` or `user`.
